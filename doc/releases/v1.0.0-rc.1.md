# Speaking Clock 1.0.0-rc.1

First source release candidate for the C / Pico SDK clock on Raspberry Pi Pico 2 W.

## Included

- Existing RTC/LCD, timer, five daily alarms, separate output volumes and LOCAL/Bluetooth MP3 playback.
- Unique Bluetooth device catalog, saved-name retention and preferred-target resume after leaving discovery.
- Wi-Fi/NTP correction with Europe/Berlin CET/CEST and offline RTC fallback.
- Local Wi-Fi provisioning helper, Flash v8 migration and alarm music tracks through 255.
- Version/profile build identity and updater verification.
- Native tests, Windows/Linux CI, current controls and prioritized roadmap.

## Validation

Four native test suites pass locally: alarm scheduling, calendar/DST and NTP validation, Bluetooth catalog behavior, and settings migration v1-v8 with simulated Flash corruption/failure.

New network/RTC coexistence, v8 persistence, Bluetooth UI refinements, extended alarm tracks and updater build verification still require hardware acceptance. Earlier Portable/Nest hardware results are documented separately. This candidate is not the stable v1.0.0 release.

## Build and configure

Build instructions and the pinned external Helix revision are in README.md. The default build includes Wi-Fi, Bluetooth and MP3 when using:

```powershell
powershell -ExecutionPolicy Bypass -File .\update-pico.ps1 -Build -Bluetooth -Mp3
powershell -ExecutionPolicy Bypass -File .\configure-wifi.ps1 -Port COM8
```

Close other serial monitors first. Provision credentials locally; they are stored on the Pico and are not printed by status commands. Check version, ntp-status, flash-info, alarm-status, audio-settings and bt-known.

Use -NoWifi with the updater for a compatible Bluetooth-only fallback. Old v7 firmware cannot read latest v8 settings after both slots have migrated.

This release provides source archives. External Helix, Pico SDK and other dependency sources retain their own licenses and are obtained through the documented build procedure.

## Deferred

Initial Bluetooth switching status 0x56 remains handled by the existing five-second retry; optimization is deferred. Physical LCD illumination/PWM and the absent German timer-completion phrase remain at the tail of ROADMAP.md, with the phrase last.
